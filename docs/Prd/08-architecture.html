MRA-PRD-008ArchitectureRev 1.0 · 8 Oct 2026

MedexRegAI system architecture

How the platform is built: a governed FDA knowledge base, retrieval-grounded AI with a citation gate, and a multi-tenant workspace for consultancies. This extends REQ §6–8 with the Submission Workspace, tenancy, integrations and deployment.

Builds onMRA-REQ-001 §6 Data architecture, §7 Canonical model, §8 AI architecture
New hereWorkspace domain (FR-13), tenancy, integrations, deployment, model update
ShapeModular monolith + workers; one PostgreSQL; object storage; Claude API
StatusProposed. ADR-001 to ADR-010 to be approved in Phase 0

1Architecture principles

  1. Provenance is structural. Every curated fact carries source, retrieval time and snapshot. Every AI-derived field also carries model, prompt version, confidence and source span (REQ §6).
  2. The model never recalls facts. It reasons over retrieved records and cites them. A deterministic citation gate removes anything that doesn't resolve (REQ §8 hard rule).
  3. Isolation in the database. Tenant and workspace isolation is enforced by PostgreSQL row-level security, including vector search, not only by application code.
  4. Registers, not repositories. Client files stay in their storage. We keep links, hashes, extracted text and structure.
  5. Boring, few moving parts. A team of about seven runs this. One relational database with vectors, one object store, one cache, one queue. Split only on measured need.
  6. Reproducible by design. Immutable raw data, snapshot-versioned curated data and indexes, versioned prompts, and stored outputs.

2System context

We never send anything to FDA. The CDRH Portal upload is done by the user outside the platform and recorded afterwards.

4Data pipeline

  • Snapshots. Curated rows carry valid_from_snapshot and valid_to_snapshot, so any past snapshot can be queried without copying tables. Indexes and dossiers are built per snapshot and switched atomically on promotion.
  • Extraction. 510(k) summaries go through text extraction (OCR for scanned files), then schema-constrained extraction with Claude Haiku 5.5 via the Message Batches API (half the price of synchronous calls). Low-confidence fields are retried with Sonnet 5.5, then routed to human review.
  • Pilot scope. The same pipeline runs on the pilot product codes first (Phase 1), then the full corpus (Phase 3). Nothing about the pipeline changes between them.

7.3Retrieval and the citation gate

  1. Retrieve. Lexical search for identifiers, plus vector search for narrative, filtered by product code, snapshot and tenant, then a cross-encoder rerank.
  2. Reason. The model gets numbered records (record ID + passage ID) and must cite them as [R:id#p].
  3. Gate. A deterministic verifier checks that each cited ID exists in the snapshot, that the quoted span matches the passage, and that every sentence with a factual entity (code, K-number, CFR, standard, date, number) carries a citation. Failing sentences are removed and logged. The gate can't be turned off.
  4. Store. The output is saved with snapshot, model, prompt version and citation list (FR-10.4).

7.4Prompt registry and evaluation

  • Prompts live in the repository with version IDs. Every AI call logs the prompt version (AiCall).
  • The evaluation harness runs held-out sets on every prompt or model change. Promotion is blocked on regression (FR-12.5).
  • Pilot sets: 50 devices with expert predicates, 300 labelled summaries, the customer's past AI letters (deficiency splitting), 100 profiles for pathway (Phase 3).

8.3Continuous gap check (PRD 2)

Any change to the plan, evidence, a linked file's hash, the profile or the pinned snapshot enqueues a gap.recheck(project) job. Completeness rules run in SQL. Precedent rules read prebuilt per-product-code expectation tables (built at snapshot promotion from extracted tests and standards). Findings are diffed against the last run, so only real changes notify users.

12Operations and observability

  • Tracing across retrieval, reasoning and the gate (OpenTelemetry), so a wrong answer can be traced to the stage that caused it (NFR-15).
  • AI cost per tenant, route and model from AiCall; alert when cost per project exceeds the unit-economics target (BP $2.40 inference per project).
  • Data freshness per source shown in the UI and the pipeline console (NFR-4).
  • SLOs: 99.5% monthly availability (NFR-2); p95 search < 3 s; full report < 10 min.
  • Runbooks for drift halt, failed promotion, model refusal spikes and restore.
